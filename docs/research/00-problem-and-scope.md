# 问题定义与范围

日期：2026-09-17  
状态：调研结论（设计输入）

## 1. 用户原声问题

在使用 Codex、Claude Code、Pi 等 Agent 工具时，**如果不使用该工具自带的模型能力**，往往无法使用其内置的 **Computer Use**。需要把 Computer Use 做成：

- **可插拔**：不绑死某一 Agent 宿主或某一模型厂商
- **可独立运行**：作为本地能力层，被任意能调 Shell/MCP 的 Agent 使用
- **跨平台**：至少 **macOS** 与 **Windows**
- **浏览器优先**：先浏览器，后桌面 App
- **不打断用户**：操作浏览器时不抢占用户正在进行的操作与系统光标
- **可接管已打开浏览器**：复用真实登录态与已有标签（在明确授权/借用模型下）
- **网页数据抓取**：结构化读取页面内容
- **首批浏览器**：Chrome、Microsoft Edge
- **CLI 化配置**：如 `vcu init model` 配置视觉模型
- **弱多模态主模型可补视觉**：主 Agent 无视觉时，可配置独立视觉模型；并考虑主/子 Agent 协同

## 2. 问题拆解

| 层次 | 问题 | 说明 |
| --- | --- | --- |
| 产品 | 能力与宿主解耦 | Computer Use 常被做成某 App 的专有功能（如 Codex Desktop 内置浏览器/CU） |
| 模型 | 多模态绑定 | 截图理解依赖视觉模型；纯文本主模型无法直接“看见”UI |
| 交互 | 抢焦点/抢光标 | OS 级键鼠注入会打断用户；浏览器期应优先页内/扩展/CDP 输入 |
| 会话 | 真实登录态 | 自动化常新开无痕配置，丢失 Cookie；需要 attach/reuse 策略 |
| 集成 | Agent 碎片化 | Cursor / Claude Code / Codex / Pi 技能目录与 MCP 配置各异，需要统一 CLI 面 |
| 平台 | macOS ≠ Windows | 辅助功能、DPI、权限模型、浏览器路径与调试端口行为不同 |

## 3. 成功判据（产品级，设计阶段）

设计被接受当且仅当文档明确回答：

1. VCU 与 BrowserSkill / Codex Browser / 通用 CDP 方案的**差异与边界**
2. **语言与仓库形态**（跨 macOS/Windows 的可执行交付）
3. 浏览器期如何做到：**不抢系统光标、可接管、可抓取、Chrome+Edge**
4. 无视觉主模型时的 **vision 配置与协同模型**
5. Agent 接入路径（CLI / MCP / Skill）是否足够“短路径”
6. 分期：MVP → 浏览器增强 → App Computer Use 的边界

## 4. 明确不做（设计阶段）

- 不实现完整 daemon/extension 代码
- 不承诺 Linux 为一期必达（可列为二期）
- 不把“替代用户日常浏览器”作为目标；目标是 **Agent 可控的并行工作面**
- 不在无用户同意时读取/外传 Cookie、密码、支付信息
